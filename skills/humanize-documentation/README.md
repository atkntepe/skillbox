# humanize-documentation

Guidance for rewriting technical documentation so it feels natural, precise, and maintainer-written without weakening the technical contract.

## Use this skill when

- Improving component documentation
- Rewriting API, prop, event, slot, or method docs
- Editing README usage sections
- Making generated or AI-written docs sound more useful and human
- Reviewing technical docs for clarity, tone, examples, and factual safety
- Writing migration notes, troubleshooting docs, or usage guides

## Avoid using this skill when

- The task is pure marketing copy
- The user wants creative brand voice instead of technical clarity
- There is no source context and the rewrite would require inventing behavior
- The request is only grammar correction with no documentation structure or tone work

## Install

```sh
mkdir -p ~/.agents/skills
cp -R skills/humanize-documentation ~/.agents/skills/humanize-documentation
```
